# REC-MIXED-CONTROL-SKEW-01 — 两路混音控制时刻差异与完整 PCM

## Goal

基线 `e72f3a3ec22f083f447fe47c1cb35fc8677ef988`（生产源码 `4bc1977`）。
确认并修复两路原生恢复/停止时刻不同时，混音适配器拒绝较早首包或遗漏较晚尾部的问题。
承接 `PX-REC-WINDOWS-AUDIO-01`、`REC-MIXED-FRAME-BOUNDARY-01`，默认录屏入口保持关闭。
先冻结原实现与原 API 回归，保存 worker PCM/根错误及完整 A/V owner 的文件。

## Requirements

1. 同一共享会话时间域中，两源恢复完成后以较早的原生恢复下界对齐输入和输出段首；
   较晚源尚未恢复的区间按原有网格记静音，不把较早源的有效 PCM 平移到较晚时刻。
   派生下界仍满足前一段 PCM/控制边界和严格恢复条件；W69 的帧取整保护保持。
   公共 A/V 扣时算法、两路原生 PTS/样本/序号、输入帧映射与固定增益保持。
2. 两源 Stop 完成后先按各自原生 Stop 验证自己的已接收区间，再将已关闭的两源确认静音到
   共同末尾；共同末尾覆盖两源的停止水位和全部合法 staged PCM。
   排出所有较晚一路的尾部；不能只为获得完整时长而以编码器静音代替有效 PCM。
   不用另一源较晚的 Stop 掩盖任一路的真实早停或倒退。
3. 保持 Exact、原生控制倒退/序号/重叠/格式/预算/溢出拒绝，以及源身份、回滚、线程回收和已接受前缀。
   不改输入重采样、不丢帧/裁剪，不新增精度容差；原完整模块与原期限保持。
4. 同字节原 API 回归先在未改生产实现上运行，分别覆盖两路谁先恢复/停止、原 worker 与原完整 owner。
   检查实际 PCM 样本和输入帧数；真实 VP9/Opus 文件、解码内容与设备验收分层，不累加通过数。
5. 修改后运行完整领域与干净源码 Windows 默认/QA 完整门禁；更新 CHANGELOG 和审查记录。

## 原 API 诊断与修复策略

原 [PX-REC-AUDIO-MIX-01](2026-09-23-recording-audio-mix.md) 第7/8项要求新共同段与完整有限尾部。
本轮九项同字节回归的有效原实现基线为1 passed / 8 failed，Cargo exit101、包装器/终端exit1。
worker恢复返回Source(LateInput)并保留960帧前缀；停止正常返回但只提交960/1920有效输入帧。
原完整恢复owner为同根音频错误并保留interrupted文件；停止owner为complete40ms，但编码输入960，
有效文件帧1920中的较晚测试信号几乎消失。原文件、实际解码PCM与三个夹具字节已冻结。
初版新视频夹具把恢复首帧设成控制确认同一时刻，不符合原视频严格时序；其日志/文件单列保留。
修正为首帧晚10ms、保守活动时刻并显式等待两源启动后，重新建立上述原生产基线；不计产品修复。

选定策略：恢复输入游标与输出段首使用两路较早原生下界，并沿用W69派生控制的帧取整保护。
停止先分别验证两路本地Stop，再将两路已关闭输入的静音水位提升到停止/合法PCM的共同最大末尾。
保持样本的原时间差，完整排出较晚尾部；另一源的较晚Stop不能掩盖本路真实早停。
