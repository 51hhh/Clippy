# PX-REC-MERGE-01 — 异常录屏分段无损恢复

日期：2026-09-21

关联路线：`PX-REC-01`

## Goal

让异常中断录屏的已提交 WebM 分段可以在结果库内恢复为一个连续、可播放和可导出的录屏，同时
保持编码画面不经过二次解码或有损重编码，并沿用现有恢复清单的路径与完整性边界。

## Requirements

1. 只有 `interrupted` 状态、`vp9-prototype` 编码且容器为 WebM 的会话显示“恢复为完整录屏”；
   AVI 诊断分段继续逐个导出，不伪装成可合并产品格式。
2. 合并前由 Rust 重新解析不透明会话 ID，并逐个校验清单、普通文件、长度和 SHA-256。前端不能
   提交分段路径、顺序、时间戳、编码参数或输出文件名。
3. 合并器只接受 Clippy 生产 writer 的单 VP9 视频轨 WebM：轨道、尺寸、时间基、无 lacing block、
   帧数、关键帧边界和单调时间戳都必须与清单一致。未知或越界 EBML 长度、额外轨道、损坏 block、
   不连续分段及资源超限必须失败。
4. 合并复用已经编码的 VP9 packet，把每段局部时间戳平移到清单的全局时间线，再由现有 libwebm
   muxer 生成新的 seek、cluster 和 duration 元数据；不能拼接 WebM 字节，也不能调用系统 FFmpeg、
   GStreamer 或重新编码画面。
5. 输出先写私有 `.recording.webm.partial`，封尾、fsync、长度和 SHA-256 校验完成后，先把
   `finalOutput` 与 `finalizing` 原子写入清单，再提升文件并写 `complete`。进程在两个提交点之间退出
   时，现有启动恢复必须能完成提升或安全回退到原分段。
6. 同一时间只运行一个恢复合并；同一会话不能重复开始。失败时保留所有已提交分段和 `interrupted`
   清单，清理尚未提交的临时输出，并在结果库提供可重试错误。成功后刷新为普通完整录屏，并可沿用
   现有按需播放、导出、定位和删除能力。

## Acceptance Criteria

- [x] 两个以上真实生产 VP9 分段可以无损 remux 为一个 WebM；输出帧 payload 与输入逐帧一致，
  `ffprobe` 可用时核对 codec、帧数和总时长。
- [x] 单分段异常会话也能恢复；输出首帧是关键帧，帧数等于清单总和，时间戳单调且总时长等于最后
  一个分段的 `startedAtNs + durationNs`。
- [x] 篡改哈希、错误尺寸/codec/轨道、lacing、非关键帧分段开头、帧数或时间戳不一致、超限 EBML
  都会失败，且不改变原清单或分段。
- [x] 最终输出与清单之间的崩溃窗口由现有启动恢复覆盖；失败和迟到重复请求不会覆盖已完成会话。
- [x] 结果库测试覆盖入口可见性、进行中状态、成功刷新、失败重试、窗口关闭及 AVI 无合并入口；
  IPC 权限仍只允许 `recordings` 窗口调用。
- [x] 默认构建不引入新的录屏依赖；feature 构建通过 Rust check/clippy/test，前端测试、TypeScript、
  Vite、IPC 合同和完整本地门禁通过。

## Out of Scope

- 不恢复未进入清单的尾段，不修补损坏 packet，不跨会话合并，也不允许用户重排或剪辑分段。
- 不删除原恢复分段，不加入音频、转码、倍速、封面缩略图或通用媒体导入。
- 不因此开放 Windows、macOS、Wayland 录屏入口，也不替代真实系统 WebView、播放器和长时间资源 QA。
