# WIN-PRIVATE-WRITE-01 — 私有文件写入前权限失败关闭

## Goal

在 Windows 代码 review 中修复 `write_private` 新文件权限准备晚于内容写入的问题。
权限准备失败时不得先写入用户内容，也不得先截断已有文件。
这是 `WIN-NATIVE-01` / W05 的独立代码修复，基于已验证 Pin 修复后的 `aefc413`。

## Requirements

1. 打开文件后，写入或截断之前必须完成私有权限准备；失败立即返回。
2. 新文件准备失败时最多保留空文件，不能包含待写入内容；已有文件准备失败时保留原有字节。
3. 成功写入仍完整覆盖旧内容、同步数据并执行写入后的权限校正；Unix 的 0600 创建规则保留。
4. 生产 `restrict_file` 与失败注入合同共用相同写入流程，验证真实文件字节和非零权限错误。
5. Windows 默认与录屏 QA 条件编译图使用本机完整门禁验证；不将故障注入当作跨账户桌面验收。

## Acceptance Criteria

- [ ] 新文件权限准备失败的回归先失败后通过，证明待写入内容未落盘。
- [ ] 已有文件权限准备失败后字节不变，成功写入仍覆盖旧内容且最终 ACL 私有。
- [ ] Windows 完整原生默认及录屏 QA 门禁通过，来源 SHA 与日志独立记录。
- [ ] CHANGELOG 与审查计划记录代码修复和未验证边界。

## Out of Scope

重写 Win32 文件创建 API、创建瞬间的空文件 DACL、目录/符号链接/硬链接竞争、跨账户权限验收、
SQLite sidecar 生命周期和目录策略；不安装新包、操控桌面、合入 dev 或发布。

## Review Evidence

`private_files.rs` 的新文件路径原先按继承权限打开、截断、写入和 sync，然后才调用 `restrict_file`。
该调用失败时函数返回错误，但待写入内容已经落盘。
配置、录屏 manifest/thumbnail 等生产调用通常已先收紧父目录；本问题是公共私有写入工具的
失败合同缺口，不声称已观察到跨账户内容泄漏。

Windows MSVC 红基线：`aefc413` 加行为不变的权限副作用入口和两项回归，exit 101，
1 passed / 1 failed；新文件为空的断言失败，证明准备错误返回前已经落盘。
修复后私有文件六项定向合同全部通过，包含新文件失败关闭、打开前/后的已有文件保护、
实际 Windows 文件/目录 DACL、较短内容覆盖与原子替换。格式检查通过。
红绿日志位于主检出的 `src-tauri/target/windows-private-write-red/`。
完整门禁与新 SHA CI 尚未执行；故障注入不代表跨账户泄漏或原生 ACL 拒绝场景的桌面复现。
