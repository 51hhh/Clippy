# REC-MEDIA-REVOKE-01 — 撤销尚在准备中的录屏播放租约

## Goal

补齐 PX-REC-PLAYBACK-01 / Requirement 4 的会话撤销合同。删除或恢复合并撤销会话时，
已进入后台但尚未签发的播放准备也必须失效，不能在撤销后重新签发旧租约。
对应 WIN-NATIVE-01 / W40；基线 116f1d3。原生产管理器已复现撤销后重新签发的缺口。

## Requirements

1. 在进入阻塞 worker 前捕获绑定会话的准备凭据；同会话撤销同时使已签发租约和待签发准备失效。
   哈希扫描的既有取消检查与最终签发都须核对同一凭据，检查与插入在同一锁内结算。
2. 撤销其它会话不能取消当前会话的准备或租约；同会话撤销后的新准备可以正常签发。
   关闭结果窗仍使所有旧准备与租约失效。不能仅递增全局代次而扩大单会话撤销范围。
3. 不为所有历史 session 永久保留代次墓碑。只跟踪仍有准备持有者的会话身份，回收过期条目，
   旧凭据不能因同名会话重新准备而恢复有效，也不能跨管理器使用。
4. 保留 8 租约上限、普通文件/长度/修改时间/SHA-256 校验、64 KiB 哈希读取与约 16 MiB
   取消检查间隔、2 MiB 协议响应、调用窗口限制、删除/合并所有权及原 IPC/默认 QA 门控。
5. 原生产 manager 用真实临时文件与受控标准线程跑红基线，修复后同组用例通过；旧五项
   媒体协议断言保留，允许内部准备接口的机械迁移。合成文件不证明真实 WebM 解码或桌面操作。
6. 干净 SHA 完整 Windows 默认/QA 门禁、源/测试/日志核对并同步同 ID 文档；两图重叠不累加。
   实际窗口/删除/合并/播放、其它宿主、本机 Linux 门禁、同 SHA CI 与安装包仍保留未验。

## Acceptance Criteria

- [x] 原管理器确实允许撤销前准备在撤销后签发；红基线与实际返回记录保留。
- [x] 无已有租约、已有租约、同会话重新准备和后台排队四种旧准备均被拒绝。
- [x] 其它会话不受影响，撤销后新准备可用，窗口 clear 使所有旧准备失效。
- [x] 准备跟踪可回收、旧凭据不能复活或跨 manager；既有媒体五项合同保持。
- [x] 干净源码完整 Windows 默认/QA 门禁与证据/记录同步，未验证项保留。

## Out of Scope

桌面操控停止。不启动应用、窗口、媒体解码、录屏或设备，不安装更新包、不推送/PR/合入。
不改变协议中已经开始的响应的结算语义，不扩展为跨进程文件锁、外部文件替换防护或媒体转码。
尚未复现的在哈希读取中间撤销时序不得记作实际已观察；源码取消检查与排队 worker 分开记录。
