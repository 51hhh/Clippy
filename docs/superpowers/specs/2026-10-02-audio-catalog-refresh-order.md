# REC-AUDIO-CATALOG-ORDER-01 — 音频设备查询按请求顺序换发目录

## Goal

基线文档 `10dbd710f9f5af19849c151a71c9bbb7923720a4`，生产源码 `2bb12f9`。
承接 WIN-NATIVE-01 与 PX-REC-AUDIO-DEVICE-01 第2/3/6/7项，解决并发设备查询的旧响应
覆盖新目录问题，使启动失败后换发的新选择不会被先前仍在枚举的查询作废。

## Requirements

1. 先用原目录 API 记录“旧查询开始、新查询开始、新查询先完成、旧查询后完成”的有限诊断，
   明确区分真实目录合同与未执行的 Tauri/设备交互，不把新接口测试冒称同字节原 API 对照。
2. 在启动异步枚举之前为 caller 预留本次查询身份；只允许该 caller 当前查询发布一次结果。
   已被新请求取代、已消费、已过期或被有界目录淘汰的查询不能发布，也不能重建旧目录。
3. 原生身份只留在 Rust，不透明 token、每类64设备、标签160 scalar、10分钟 TTL、最多32目录
   和 caller/类别/模式约束保持。未发布的查询不能被设备选择消费；默认无 token 行为保持。
4. 枚举继续在 blocking worker 执行；失败换发空目录以保留系统默认选择。新目录发布之后，
   旧查询的成功、失败或延迟完成都不能修改新目录。其它 caller 的查询互不取代。
5. 保留原完整目录与前端测试；增加确定性顺序、一次发布/消费、过期/淘汰保护及前端启动重试
   的旧响应保护。运行 Windows 默认/QA 完整门禁，记录实际源码和通过/失败/跳过。
6. CHANGELOG、原设备规范和审查引用同 RID；同 SHA CI、原生设备与桌面验收继续分层保留。

## Acceptance Criteria

- [ ] 原 API 诊断保存新目录被旧完成覆盖的真实结果及输入/输出哈希。
- [ ] 查询在异步边界之前预留；旧完成不能覆盖当前目录，当前选择正常一次消费。
- [ ] TTL/容量/caller/发布与消费保护、空目录默认选择以及原完整测试通过。
- [ ] 前端启动重试旧响应保护与干净源码 Windows 默认/QA 完整门禁通过。
- [ ] 当前源码同 SHA 跨平台 CI、release 与真实设备/桌面行为完成。

## Out of Scope

不操控桌面，不启动应用或音频设备，不安装、签名或新增系统工具，不推送/PR/合入/发布。
不改变录屏默认入口、热切换、设备枚举平台实现、音频混音/时间线或既有测试期限。
旧失败根因、Windows 10/多屏、其它宿主与长时同步仍按现有未验证记录保留。
