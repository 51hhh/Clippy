# REC-MIXED-STOP-READY-BOUND-01 — 混音停止输出的固定内存上限

## Goal

基线文档 `1e17b34166c4838c23db9c62b51f25534f2c5a3a`，生产源码 `02005c9`。
承接 WIN-NATIVE-01 及 PX-REC-AUDIO-MIX-01 第5/8项和固定 ready 上限验收。
先用原 API 在未改生产实现上复现活跃 Stop 一次性生成剩余全部 PCM 的问题；
确认后使混音停止输出按固定预算排出，保留合法完整尾部和原背压失败策略。

## Requirements

1. 原 API 的适度有限间隔诊断先于生产修复；源/原 worker/完整 A/V owner 对照记录真实
   根错误、已接受 PCM、两源 Drop、journal/已有媒体。规范夹具同字节，旧完整模块/期限保留。
2. 混音 Stop 不随控制时间间隔分配全部 ready PCM；每次停止尾部读取至多一秒 stereo PCM，
   输出单块仍最多20ms。大间隔仅用修复后的安全诊断，不在原实现上制造内存耗尽。
3. 全部合法 PCM、固定0.5增益、序号、绝对时间戳与缺包静音区间保持。正常停止必须排空
   全部有限尾部后才 pipeline.finish，不能以拒绝所有长间隔、截断尾部或降低Stop时刻规避问题。
4. 原生两源 Stop 均尝试；控制倒退/早停、格式/预算/源错误、暂停中实际PCM、时间线溢出和
   原一秒 pipeline 背压仍失败关闭，保留已接受前缀/恢复分段。派生Stop须覆盖最终输出取整末尾。
5. 若原接口单次全量语义需调整，读取合同与所有生产调用者必须同步，有限空批表示结束；
   默认无尾部和现有平台一次性尾部仍正确。未经排空不能封尾，排尾错误不能伪造完成。
6. 修复后运行完整录屏领域和干净源码Windows默认/QA完整门禁，真实codec文件另核。
   CHANGELOG/规范/审查同RID；旧失败根因继续未明，构建/文件/合成源不能替代设备或同SHA CI。

## 原 API 诊断与选定策略

原九项同字节规范夹具2 passed / 7 failed，Cargo101、包装器/终端1。
两秒有限间隔的原混音源首批96960帧（无首包97920），超过一秒48000帧固定预算。
拟议分批合同的合成夹具经原worker只读取一次，完整有限尾部只有1920帧而不是2880帧；
下一批夹具错误被忽略。原完整A/V owner两例均complete60ms/1920输入，错误例也错误完成。
这证明新增分批输出必须同步原worker；不冒称原生平台一次性尾部已复现漏包。
原pipeline一秒Backpressure和真正原生Stop错误保护通过。实际journal/媒体、两音源/一视频源Drop保存。
原122份录屏文件的生产实现/旧完整模块/期限保持；规范夹具冻结于原API审计。

选定策略：Stop只验证/冻结最终水位，按输出原点和最终帧计算并覆盖派生控制末尾；
不提前生成全部PCM。take_stopped_chunks每批至多一秒，空批结束；worker循环读取到空批后
才finish，后续批错误立即失败。原生单次有限尾部仍适用，混音读取每个输入的全部有限批，
保留原staging/格式/控制/暂停/背压保护。不降低Stop下界、不截掉PCM或用静音替换合法样本。
修复后单列极大间隔安全用例；不把它冒称原实现同字节对照。
