# REC-MIXED-FRAME-BOUNDARY-01 — 混音输出帧与源控制边界

## Goal

基线 `0cbf42c8c9ad4d3b0bb5721906d2d4573294ffa7`（生产源码 `aac5e0a`）。
确认并修复 MixedAudioSource 原生纳秒控制边界与 48 kHz 输出帧取整不一致的问题，
承接 `PX-REC-WINDOWS-AUDIO-01`、`REC-AUDIO-ACTIVATION-BOUNDARY-01`。
先冻结原实现与同组回归，保存 worker 根错误、PCM 前缀、完整双轨 owner 的结果与文件。

## Requirements

1. 继续按现有公共 48 kHz 网格对齐两路输入，保持输入原生 PTS、样本、序号、增益、预算和静音水位。
   已知启动/恢复下界与派生混音输出使用一致边界，首块不能早于源返回的下界。
   输出时间戳可按该段控制边界与已输出帧数派生；不能放宽 Exact pipeline 的迟到或重叠检查。
2. 派生控制时刻必须覆盖已输出 PCM 的末尾；合法停止尾部须全部经过原 pipeline。
   归一化发生在混音适配器，不把它声明成 WASAPI 100 ns 精度，不改原生源时刻或公共 A/V 扣时规则。
   紧接暂停的合法恢复仍须严格晚于派生暂停时刻，并使首块符合该恢复下界。
3. 在归一化之前保留原生控制时刻倒退、输入序号/区间重叠、早停、格式、预算和溢出的拒绝。
   两源控制失败的身份、回滚、线程回收和已接受前缀保持；不裁剪输入帧来掩盖边界差。
4. 同字节原 API 回归先在未改生产实现上运行，记录失败；修改后运行同组及完整领域。
   旧完整测试模块与原期限保持，不将隔离重跑归为历史失败根因证明。
5. 完整合成 A/V 会话使用原 owner、真实 VP9/Opus 与 journal；源码门禁与设备验收分层。

## 原实现诊断与选定策略

同组原 Rust API：2 passed / 8 failed，native Cargo exit 101；未改生产代码，旧完整模块/期限保持。
已保存启动首块早 5000 ns、恢复 SourceTimestampNotIncreasing、尾部不足 833 ns 的
FinishBeforeBufferedAudioEnd、worker PCM 前缀及原双轨 interrupted 文件；不是设备运行证据。

保留原有绝对网格上的输入映射；输出段首锚定到该段派生启动/恢复边界，再按相对帧数产生时间戳。
派生控制时刻取原生两源最大时刻、已输出 PCM 末尾和已返回控制下界的最大值。
恢复至少晚于派生暂停 1 ns，再锚定输出；两路原生控制分别先检查不倒退，相等不当作倒退。
输出 PTS/末尾/下一序号的溢出在移动游标或释放 staging 前拒绝。
以上只修正混音适配器派生边界，不改两路原生 PTS、样本或公共暂停算法。
