# REC-MANIFEST-SHARING-01 — Windows 录屏清单临时共享冲突

## Goal

基于 W55 文档 `9a7a6e2` / 源码 `120b3ad`，用真实 Windows 文件共享句柄独立检查
录屏清单替换失败是否导致原采集/编码 worker 提前退出。W53 的历史 30 秒超时只留下
等待断言，不能据此归因；新的受控复现不冒称已解释那次历史失败。

## Requirements

1. 使用原 DiagnosticRecordingSession、MJPEG encoder、三帧 pipeline、journal 与同样
   10 FPS/200 ms 分段配置。初始清单真实句柄允许读写而不共享删除，在第三个原帧后
   短暂持有并释放。保存 worker 原错；不操控桌面、连接设备或改原测试与 30 秒期限。
2. 只在原生证据复现后修改生产。初始原生红在约 0.30 秒取得实际 encoder 的
   Journal 原子清单写入错误 5；不能把它冒称为错误 32。仅 Windows 录屏清单发布
   可对原始错误 32/33，或错误 5 且原生删除访问探针确认源/目标的共享拒绝 32，做
   最多 21 次尝试、500 ms 等待预算、每次最多 25 ms 间隔；其它错误立即返回。
   原生一次文件调用自身的阻塞不声称受该等待预算限制。
3. 私有 temporary、ACL、原子替换和 sync 顺序保持，原权限工具与其它保存路径不改。
   已提升而后续 ACL 失败时源已不存在，不再重试；不删除目标、降低 ACL 或忽略错误。
   删除访问探针只打开现有文件并关闭句柄，使用全部共享与不跟随 reparse point 标志，
   不实际删除、不改变 ACL；探针成功或返回权限拒绝均不允许把错误 5 归为共享冲突。
   清单先提交、分段后提升及恢复哈希/统计合同不改，采集帧率/时间/队列预算不改。
4. 相同运行期夹具在原 Git 源码红、新源码绿；新 retry API 合同只在绿色图执行。
   原完整测试模块与历史失败保留，真实 AVI/清单/哈希与报告核对，永久冲突仍失败关闭。

## Acceptance Criteria

- [ ] 真实 Windows 临时共享冲突取得原 session/encoder 错误或否定证据。
- [ ] 如复现，Windows 清单有界恢复且其它错误/永久锁/已提升情形保持失败关闭。
- [ ] 同字节运行期旧实现红、新实现绿；原测试/预算/权限与恢复保护保持。
- [ ] 干净 source SHA 完整 Windows 默认/录屏 QA 门禁通过，重叠/ignored/skip 单列。
- [ ] 当前 SHA 三宿主/codec CI、真实设备/安装器/多屏与历史 AVI 超时原因核实。

## Out of Scope

历史 W53 根因仍未证明，不增加原测试超时或用重跑通过冒称解决。其它文件/权限路径、
Linux/macOS 行为不改；桌面、设备、工具安装、证书、推送/PR/合入/发布继续停止。
本 SHA release 与实际 WGC/WASAPI 长时同步、Windows 10/混合 DPI/多屏仍未验。
