# PX-PIN-HISTORY-01 — Pin 工作区历史浏览器

日期：2026-09-21

路线标识：`PX-PIN-HISTORY-01`

## Goal

让用户在所有 Pin 都已关闭或位于其他桌面时，仍能从一个全局入口浏览、重开、归组和移除自己明确保存的
Pin 工作区条目，同时保持主窗口底部只有“收藏 / 全部”两个剪贴板页签。

## Requirements

1. 托盘增加“贴图工作区”入口，打开独立、可调整大小的无边框窗口；主剪贴板列表不增加第三个页签。
2. 列表接口只返回工作区 ID、分组、内容类型、有限文本摘要、显示尺寸、展示状态、更新时间和是否已打开，
   不向 WebView 返回根图、修订文档、数据库路径或文件路径。
3. 图片缩略图按可见行惰性请求；后端从受管根图和累计修订重新渲染后生成有界缩略图，最多同时处理两张，
   并按 `workspace id + rendered hash` 使用有限缓存。列表加载不得读取所有图片 BLOB。
4. “显示”使用工作区 ID 在后端重新读取记录：已打开时只显示、聚焦并给出既有 Pin 反馈；已关闭时复用启动
   恢复链创建窗口。前端不能提交窗口 label、图片路径或任意修订内容。
5. 归组、创建分组、重命名和删除分组复用现有存储规则。外部修改若影响已打开 Pin，后端必须同步其
   `workspaceId / workspaceGroupId`，避免窗口内管理器继续显示旧状态。
6. 移除工作区条目必须先内联确认。已打开 Pin 只转为临时 Pin 并继续显示；已关闭条目直接删除。根图片仍由
   `image_revisions` 外键可达性保护，不能因移除一个工作区条目破坏其他修订或历史。
7. 独立窗口拥有最小 IPC 白名单、后端拖动和关闭命令；主题和语言沿用当前配置，错误可重试，空状态可辨认。

## Acceptance Criteria

- [x] 冷启动或关闭某个已保存 Pin 后，仍可在全局窗口看到它并重新打开。
- [x] 已打开条目执行“显示”不会创建第二个窗口；移除后原 Pin 保持打开并变成临时 Pin。
- [x] 分组筛选、归组、创建、重命名和删除在刷新后保持一致；删除分组只把成员移到未分组。
- [x] 图片列表首屏不通过摘要接口读取图片 BLOB；缩略图有并发、像素和缓存上限，修订更新后不会命中旧缓存。
- [x] 窄至 420 px 时标题、筛选、行操作和确认区仍可用，键盘 `Esc` 可关闭确认或窗口。
- [x] Rust 存储/状态测试、React 交互测试、IPC 合同、TypeScript、Vite 构建和完整本地门禁通过。

## Out of Scope

- 不把 Pin 工作区混入剪贴板搜索、收藏或清理策略。
- 不增加跨设备同步、云端共享、自由排序、批量选择或工作区画布编排。
- 不在浏览器中编辑标注；编辑仍从重新打开的 Pin 进入。
- 不改变临时 Pin 的一次性语义，也不自动把所有 Pin 保存到工作区。
