# REC-AV-CONTROL-TIMELINE-01 — 双轨控制共用暂停扣时

## Goal

在原双轨会话中验证并修复两条 source 的控制耗时不同造成的恢复后媒体时间错位。
基线 `790d9f6461bd3036c604af745e3086080d977558`；承接
`PX-REC-AV-SESSION-01` 的双轨控制与真实空洞合同，不更改共享源时钟或默认 feature。

## Requirements

1. 同一会话中的视频和音频继续使用同一个源时间域；同一原始采样时刻应映射到同一媒体时刻。
2. 暂停扣除两源都停止的公共区间：起点取两个有效暂停时刻的较晚者，终点取首先恢复的
   视频 source 的有效时刻。其它源的停止/启动耗时保留为该轨真实空洞，由原 CFR/PCM 补齐。
3. 两源都已暂停后，只有较早暂停的时间线需要延后媒体暂停边界；不重复调用 source 控制。
   音频恢复仍验证原 source 返回时间戳，媒体扣时使用视频的恢复边界，不能掩盖坏原始时间戳。
   媒体暂停边界与源暂停边界分开；WASAPI 包末尾可能晚于视频快速恢复或停止，公共区间
   无重叠时扣零，不以媒体边界替换原 source 校验下界，暂停中封尾同样按实际交集扣时。
4. 原纯视频/独立音频 pause/resume API、首帧状态拒绝、正常停止、错误传播、回滚、线程内
   source 亲和性、队列/FPS、epoch、分段、原测试及期限保持。控制协调错误必须关闭失败会话。
5. 新合同先使用原 owner 控制与实际 pipeline 队列，另外调用原完整 session/真实 codec/文件
   验证产物。合成帧/音源不能记为真实 WGC/WASAPI、设备漂移或桌面验收。

## Acceptance Criteria

- [x] 原实现的不同控制边界产生恢复后错位，并保存旧 API 同字节夹具及实际结果。
- [x] 暂停差、恢复差、多轮差、相同边界、暂停中停止和恢复真实空洞均通过；source hooks 不重复。
- [x] 坏音频恢复时间戳仍被拒绝；完整双轨会话的实际 WebM/manifest 与共同媒体时长一致。
- [ ] 原完整测试模块/期限保持，冻结干净 SHA 的 Windows 默认/QA 完整门禁通过。
- [ ] 同 SHA 跨平台 CI、其它宿主、当前 release、真实设备/桌面/长时同步/Win10/多屏另验。

## Out of Scope

不启动应用或桌面/设备，不安装、推送、合入或发布；不开放默认录屏 feature。
不做源时钟漂移重采样，不改帧率、容量、时间原点或其它 UI 行为。
W53 历史 AVI 超时和 W59 历史 Opus 失败继续不归因于本次独立对照。
