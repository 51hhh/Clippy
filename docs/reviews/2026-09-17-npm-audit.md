# 2026-09-17 npm 依赖漏洞核查

## 范围与授权

- 范围：`src/package.json` 与 `src/package-lock.json`；
- 需求记录：[`2026-09-17-architecture-hardening-plan.md`](../superpowers/plans/2026-09-17-architecture-hardening-plan.md) Phase 9；
- 外发授权：项目所有者在 2026-09-17 明确允许继续按计划实施，因此允许向 npm 漏洞服务发送依赖树和版本元数据；
- 方法：只读执行 `npm audit --json`，随后审阅依赖路径和生产可达性；没有执行 `npm audit fix --force`。

## 初始结果

`npm audit --json` 报告 2 个 moderate 条目，实际对应同一个 advisory：

| Advisory | 依赖路径 | 受影响范围 | 修复版本 | 初始结论 |
|---|---|---|---|---|
| `GHSA-82fw-gwwq-j7x9` / source `1193683`、`1193684` | `vitest@4.1.10` → `@vitest/mocker@4.1.10` | `vitest >=2.1.0 <4.1.11` | `4.1.11` | 生产不可达；测试工具链可达 |

漏洞类型是 redirect mock 路径穿越/任意文件读取（CWE-22，CVSS 5.9）。npm 把直接依赖 `vitest` 和
传递依赖 `@vitest/mocker` 分别计数，所以总数是 2，并不代表两条独立攻击链。

## 可达性分析

结论：**Tauri 正式应用与 Vite 生产包不可达，开发/测试环境可达。**

证据：

- `vitest` 位于 `devDependencies`，lockfile 中 Vitest 全套包均标记 `dev: true`；
- `@vitest/mocker` 只经 `vitest` 引入；
- 仓库中对 `vitest` 的源码导入全部位于 `src/tests/`；
- 生产构建后的 `dist/` 不包含 `vitest` 或 `@vitest/mocker`；
- 应用运行时依赖、Rust/Tauri bundle 和用户数据处理链不加载测试 runner。

开发者或 CI 主动运行受影响版本的 Vitest 时仍会进入该工具链，因此“生产不可达”不等于可以长期
忽略。补丁版本可用且不要求 Vite、Node 或 Tauri 主版本变化，选择直接升级。

## 修复

- 将直接开发依赖 `vitest` 从 `^4.1.10` 升到 `^4.1.11`；
- lockfile 同步升级 Vitest 组件到 4.1.11；
- npm 同时把测试工具链使用的 `@jridgewell/sourcemap-codec` 从 1.5.5 更新到 1.6.0；
- 生产 dependencies 数量和版本未改变；没有使用强制自动修复。
