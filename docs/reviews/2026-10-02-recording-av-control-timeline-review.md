# WIN-NATIVE-01 / W63 — 双轨控制使用公共暂停区间

需求 `REC-AV-CONTROL-TIMELINE-01`；基线 `790d9f6461bd3036c604af745e3086080d977558`；
分支 `codex/recording-av-control-timeline`。修改生产前建立规格与八条原 API 合同。

## 发现与修复

原 owner 顺序暂停/恢复，但两条 timeline 各扣自己的控制间隔。原八项运行期合同
2 passed / 6 failed：暂停差造成 20 ms 偏差，恢复差造成 40 ms 偏差；五轮每轮控制
累积 20 ms，最后同一原采样时间对应视频 3.7 s、音频 3.6 s。
暂停中停止的两轨时长分别 80/100 ms；音频较晚恢复的真实空洞错误从 140 压到 100 ms。

采集线程返回已验证的原控制时间戳，owner 以较晚暂停时刻作为共同起点，在较早轨的
采集线程延后媒体暂停边界。视频首先恢复，其有效时间作为公共恢复终点；音频仍调用自身
source 一次并验证实际恢复时刻，但只扣公共区间，保留较晚激活的空洞。媒体元数据
协调不调用原生源；失败回复及原 join 根因保持，owner 协调失败中止两条 pipeline。
音频保留实际 source 恢复下界，拒绝早于该下界的 PCM。新入口只在 Opus/WebM feature。
