# Clippy 全面重构：截图、Pin、编辑与翻译融合

## Goal

在保持 Linux 轻量剪贴板管理器定位的前提下，完成 Clippy 的平台层、窗口层和前端架构重构，将截图选区、图片编辑、Pin 贴图、OCR 与翻译整合为连续且可靠的工作流，并解决 Wayland 自动粘贴频繁授权和 X11 主窗口显示异常。

## Requirements

### 1. 平台与自动粘贴

- 明确区分 X11、Wayland 和不支持自动输入的环境，不以 `DISPLAY` 是否存在判断 Wayland。
- 建立统一 `PasteBackend`，至少包含 X11 XTest、Wayland RemoteDesktop Portal 和 Copy-only fallback。
- X11 自动粘贴不请求 Portal 授权，并在粘贴前可靠恢复原活动窗口。
- Wayland 首次启用自动粘贴时请求键盘控制权限；Portal v2+ 使用 `persist_mode=2` 和滚动更新的 `restore_token` 恢复授权。
- Portal 会话在应用生命周期内复用，失败时只尝试恢复一次，不得每次粘贴循环弹窗。
- 自动粘贴可关闭；不支持、拒绝或失效时必须保留“仅复制”路径。
- restore token 按敏感凭据处理，不写入宽松权限的普通明文配置。

### 2. 窗口与 X11 显示

- 建立统一窗口控制层，负责显示、隐藏、焦点、当前显示器、工作区约束、logical/physical 尺寸换算和位置记忆。
- 主窗口支持按鼠标、当前显示器或记忆位置显示，并始终限制在显示器工作区内。
- 修复 X11 下主剪贴板页面的空白、黑屏、尺寸、重复标题栏、缩放或越界问题；具体根因通过诊断日志和平台矩阵确认。
- WebKitGTK 优化必须可验证、可回退，不得用全局强制策略掩盖平台问题。
- 多窗口共享状态必须有单一事实源，避免前后端布尔状态竞争。

### 3. 前端重构

- 分阶段将主窗口、Pin 和截图界面统一到 React + TypeScript；禁止一次性删除可工作的旧入口后再补功能。
- 所有 Tauri IPC 通过 typed wrapper 访问，业务组件不得直接调用裸 `invoke`。
- 按 feature 拆分 clipboard、preview、capture、editor、pin、translation、settings 和 shared 模块。
- 用户内容默认使用 React 文本节点或 `textContent`；富文本继续经过 DOMPurify 严格清洗。
- 新 UI 支持中英文、键盘操作、焦点可见、tooltip 和无障碍名称。

### 4. 截图融合

- 快捷键触发冻结画面覆盖层，而不是必须先进入大尺寸编辑窗口。
- 支持多显示器、混合缩放、拖拽选区、智能窗口命中、选区移动和八方向缩放。
- 采用显式 CaptureSession/RAII 生命周期，防止并发截图、错误路径和取消路径泄漏帧或窗口。
- 选区完成后可直接复制、保存、Pin，或进入高级编辑。
- Rust 保留冻结帧，前端传递选区和编辑参数；避免完整图像在 IPC 中重复 base64 往返。
- 保留并完善 Wayland wlroots、Portal、GNOME Shell、X11/xcap fallback。

### 5. 图片编辑

- 基础工具包含选择、画笔、矩形、箭头、文字、模糊/马赛克、撤销和重做。
- 标注以对象/命令模型管理，可选择、修改、删除，导出时与图像合成。
- 支持亮度、对比度、饱和度、灰度和圆角；复制、保存、Pin 输出一致。
- 高频 pointer/wheel 更新经 rAF 合并，大图加载和编辑器依赖按需加载。

### 6. Pin 贴图

- 建立统一 PinManager，管理内容来源、窗口、缓存文件、原始尺寸、缩放、透明度、锁定、位置和资源释放。
- 普通剪贴板 Pin 与截图 Pin 使用同一窗口和交互体系，但保留文本与图片的适配渲染。
- 图片 Pin 无装饰、透明、始终置顶，图片本体不套装饰卡片；为阴影、控件栏和编辑工具预留窗口空间。
- hover/focus 时显示图标控件，至少包含复制、关闭、锁定、缩放和透明度；截图 Pin 增加保存和编辑。
- 拖动越过阈值后才启动原生窗口拖动；缩放使用真实窗口尺寸并限制在当前显示器工作区。
- Pin 的 Copy 只能复制，不得复用带自动粘贴副作用的 `select_clip`。
- 创建时避免空白/黑色首帧，关闭后清理缓存和管理状态。

### 7. OCR 与翻译

- 文本条目、HTML 纯文本、OCR 结果和截图选区均可作为翻译输入。
- 截图翻译链路为“选区 -> 本地 OCR -> 翻译文本”，默认不上传原始图片。
- 建立独立翻译领域层和 `TranslationService` 接口；实现至少一个稳定可配置服务，并保留多服务扩展能力。
- 支持源语言自动检测、目标语言选择、超时、结构化错误、单服务重试和 request-id 防陈旧结果覆盖。
- API 密钥使用系统 Secret Service/keyring；不得降级为明文 secrets.json。
- 翻译必须显式触发；敏感条目禁止自动发送，并显示目标服务/隐私提示。
- 翻译结果可复制，且与剪贴板 watcher 的 skip/存储语义明确一致。
- Translator 示例为 GPL-3.0，只能参考行为和架构后独立实现；不得复制其源码。

### 8. 质量与发布

- Flashot MIT 代码如直接复用，保留许可证声明和来源记录。
- 为纯几何、状态机、会话清理、授权恢复、Pin 生命周期、翻译服务和陈旧响应增加自动化测试。
- 建立 X11/Wayland 手工矩阵和可自动化的 Xvfb/DOM smoke test；记录无法在 CI 模拟的 Portal 人工验收。
- 保持 deb/AppImage 构建、更新器、托盘、剪贴板监听、搜索、收藏、预览和设置功能可用。
- 通过 `scripts/ci-local.sh` 完整质量门禁，并对未运行项给出准确说明。

## Acceptance Criteria

- [ ] X11 选中剪贴板条目可恢复原窗口并自动粘贴，无系统授权弹窗。
- [ ] Wayland 首次授权后，同一应用会话内不再弹窗；Portal v2+ 重启后可使用 restore token 自动恢复，失效时只提示一次。
- [ ] 自动粘贴不可用或被拒绝时，条目仍可正确复制且不会误注入按键。
- [ ] X11 主页面在 deb/AppImage、常见缩放和多显示器场景下非空白、非黑屏、不越界、无双标题栏。
- [ ] 截图快捷键进入冻结覆盖层，可选区域或窗口，并可移动/缩放选区。
- [ ] 截图可直接 Copy/Save/Pin，也可进入高级图片编辑。
- [ ] 图片编辑支持基础标注、模糊、撤销/重做和图像调整，三种输出一致。
- [ ] 文本/图片/截图 Pin 使用统一管理和视觉体系，控件、缩放、透明度、锁定、拖动与清理可靠。
- [ ] Pin Copy 不触发自动粘贴；关闭所有 Pin 后无残留缓存或管理记录。
- [ ] 文本、OCR 和截图选区均可显式翻译；敏感条目不会被自动发送。
- [ ] 翻译请求支持超时、重试、request-id 和安全密钥存储。
- [ ] 原剪贴板、搜索、收藏、预览、OCR、设置、托盘、更新和快捷键行为无回归。
- [ ] Rust fmt/check/test/clippy、前端 test/typecheck/build、quick CI 和完整 CI 全部通过。
- [ ] X11、Wayland 和 Portal 授权人工验收矩阵有结果记录。

## Out of Scope

- 不通过 root 常驻服务或自带 uinput 守护进程绕过桌面安全模型。
- 不承诺所有桌面环境永久免除 Portal 确认；权限撤销和后端不支持时允许重新授权。
- 不复制 Translator 的 GPL 源码。
- 本阶段不扩展 macOS/Windows 发布目标。
- 不优先实现滚动截图；仅在核心截图、Pin、编辑、翻译链路稳定后评估。
