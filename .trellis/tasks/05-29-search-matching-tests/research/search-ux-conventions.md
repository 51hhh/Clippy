# 主流搜索 UX 调研：剪贴板/历史/启动器/命令面板

## 结论

主流用户对本地历史搜索的直觉是“输入越少越宽松，包含即可命中；输入变长后可以更精准”。用户输入一个字母时，如果历史中有可见文本包含该字母，通常预期能看到结果，而不是要求该字母成为独立分词。

## 常见约定

- **短输入宽松匹配**：1–2 个字符通常使用 substring/prefix 包含匹配，避免空结果。
- **长输入可用 token/FTS**：3 个字符以上可以用词项、前缀或全文索引提高性能。
- **保留时间排序**：剪贴板历史工具通常优先按最近使用/最近复制排序，而不是复杂相关性排序。
- **特殊字符不能报错**：搜索框是普通文本框，不应暴露底层查询语法错误。
- **空结果应可信**：如果用户看到空结果，应表示确实没有包含项，而不是搜索语法太窄。
- **搜索范围应符合内容呈现**：用户能看到的文本、OCR 文本、标题/预览文本，通常都应该可搜。

## 映射到 Clippy

- 当前 `MATCH "a"` 对单字符太严格，不符合直觉。
- MVP 应优先修复：短输入 substring，长输入 FTS prefix + fallback。
- 排序继续使用 `created_at DESC`，符合剪贴板历史语境。
- 搜索字段建议覆盖 `text_content` 和 `ocr_text`；HTML 去标签可后续做。

## 推荐 MVP

1. 输入 1–2 字符：`LIKE '%query%'`，覆盖 `text_content`/`ocr_text`。
2. 输入 3+ 字符：先 FTS prefix，若无结果或 FTS 报错则 fallback 到 `LIKE`。
3. 所有输入过滤控制字符，LIKE 特殊字符转义，FTS 特殊字符安全处理。
4. 新增搜索测试覆盖短输入、中文、特殊字符、收藏过滤、FTS 索引修复。
