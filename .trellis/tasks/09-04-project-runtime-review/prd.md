# 全项目功能、性能与运行时内存审计

## Goal

以当前 `dev` 为事实基线，系统检查 Clippy 的全部用户功能、跨层数据流和资源生命周期；修复可复现的
正确性问题，降低关键交互延迟和长期运行内存，同时保持截图、Pin 与可编辑 PNG 的原始像素质量。

## Requirements

### 1. 完整功能审计

- 建立主窗口、剪贴板监听/写入、搜索/收藏/预览、快捷键/托盘、自动粘贴、截图、编辑、Pin、OCR、
  翻译、设置、更新与发布的功能—实现—测试映射。
- 检查 Rust/前端 IPC 契约、错误与取消路径、并发状态、窗口关闭和应用退出时的资源释放。
- 对无法自动化的系统集成功能明确记录平台、会话、前置条件和未验证边界，不以编译通过冒充实机通过。

### 2. 响应性能

- 量化启动、主窗口显示、剪贴板选择、搜索、截图首帧、选区合成和 Pin 首帧的关键阶段；日志计时必须
  覆盖真实成本，不能只测锁内取引用等局部步骤。
- 优先消除主线程阻塞、重复全量图像处理、冗余 IPC/序列化、无界事件或定时器工作。
- 保持 v0.1.20 已验证的 GNOME Wayland 混合缩放双屏截图首帧基线：中位数低于 800 ms，P95
  低于 1200 ms，且协议失败时存在无损兼容路径。

### 3. 运行时内存

- 盘点常驻共享状态、数据库缓存、预览缓存、截图会话、Pin 原图/补偿图、WebView、大对象 URL、监听器、
  定时器和后台任务的所有权与释放点。
- 对空闲、剪贴板压力、连续截图取消、连续 Pin 打开/关闭和编辑保存建立可复现实验；区分 allocator
  保留、可回收缓存与真实对象泄漏。
- 修复无界增长、关闭后仍被强引用、同一大图不必要复制或后台任务污染新会话的问题。

### 4. 质量与画质边界

- 截图、复制、保存、Pin 和可编辑 PNG 继续以原始 RGBA/原图为权威事实源；预览优化不得降采样、
  改变合成语义或丢失 iTXt 工程数据。
- 所有修复补充对应自动化测试、基准或真实运行证据；高/严重 review finding 必须关闭或明确阻断原因。
- 注释、文档和 commit 使用中文；提交按单一关注点拆分并遵循 Conventional Commits。

## Acceptance Criteria

- [x] 功能审计矩阵覆盖全部已声明功能，并为每项给出自动化、实机或缺失证据。
- [x] Rust `fmt/check/clippy/test`、前端 `test/typecheck/build`、DOM/Canvas smoke 全部通过。
- [x] Linux、Windows、macOS 原生 CI 在同一提交上通过；平台实机边界准确记录。
- [x] 关键响应路径有可重复的阶段计时；已确认回归均修复且没有以兼容性换取明显性能倒退。
- [x] 截图双屏首帧维持中位数 < 800 ms、P95 < 1200 ms，且无黑屏、缺帧或 WebKit 崩溃。
- [x] 空闲及重复截图/Pin 压力实验有 RSS/PSS 与对象生命周期证据；不存在已知无界增长。
- [x] 截图、Pin、复制、扁平保存和可编辑 PNG 的尺寸、像素摘要及工程恢复测试通过。
- [x] review 中所有高/严重问题已修复；其余问题有优先级、影响、证据和后续处理结论。
- [x] 变更记录、Trellis 研究/验证记录与实现一致，工作区无遗漏的已跟踪改动。

## Out of Scope

- 不通过降分辨率、降低刷新正确性、移除兼容后端或减少支持平台来换取指标。
- 不在缺乏实机证据时宣称所有桌面环境行为一致。
- 不进行与发现无关的一次性全量框架迁移，也不重写稳定模块只为统一风格。
- 不把操作系统、WebKit 或合成器的外部缺陷伪装成应用已修复；应用侧可规避项仍需评估。
