# 修复图片预览、OCR 与可编辑 PNG 回归

## Goal

修复图片/OCR 侧栏改动后 review 确认的异步竞态和性能问题，同时在不恢复主界面“打开图片”按钮或 `Ctrl+O` 的前提下，让保存的可编辑 PNG 工程能够重新进入贴图编辑流程。

## Requirements

- 图片、HTML、Markdown 和代码预览的异步结果只能修改发起该次渲染的当前条目；切换条目后，旧请求不得写入图片、元信息、错误状态或 OCR。
- 旧图片请求不得在切换后启动新的 OCR；OCR 完成后的配置读取、复制结果和状态更新同样受当前渲染代次保护。
- Tesseract 可执行文件探测结果在进程内缓存，安装成功后能够失效并重新探测。
- OCR 识别设置全局并发上限，并合并同一 clip ID 的同时请求，避免重复子进程与重复数据库写入。
- 主界面维持现有设计：不恢复普通“打开图片”按钮，不恢复 `Ctrl+O`；普通图片继续通过系统剪贴板自动进入队列。
- 支持把带 Clippy 工程 iTXt 的 PNG 拖入主窗口后继续编辑；普通 PNG 或无效文件不得绕过剪贴板队列创建贴图。
- 剪贴板图片在 PNG 编码前校验尺寸、像素数和 RGBA 长度，拒绝明显异常或超出安全预算的输入；不得缩放或降低合法图片分辨率。
- 更新用户文档、原生 QA 和构建目标说明，使其与当前三平台 CI 和工程重开方式一致。

## Acceptance Criteria

- 可控异步测试证明：图片 A 请求未完成时切到 B，A 的成功、失败、`onload`、OCR 及延迟配置结果均不能污染 B。
- 首次延迟加载渲染库时切换条目，旧文本不会覆盖新条目。
- 后端测试证明同一 clip 的并发 OCR 只执行一次；不同请求不会超过规定并发数；缓存命中不启动 OCR。
- Tesseract 路径缓存有纯函数/状态测试，安装成功路径会明确失效缓存。
- 拖入有效可编辑 PNG 会创建可继续编辑的 Pin；拖入普通 PNG、多个文件或非 PNG 时安全忽略并给出明确日志/提示。
- 剪贴板图片预算边界、尺寸溢出和 RGBA 长度不匹配均有测试；合法 4K/8K 输入不发生缩放。
- `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`、`npx vitest run`、`npx tsc --noEmit` 和 Vite build 全部通过。

## Out of Scope

- 恢复主界面图片打开按钮或 `Ctrl+O`。
- 将普通图片文件拖放作为新的通用导入方式。
- 更换 OCR 引擎、引入动态链接的 Tesseract 库或云端 OCR。
- 为降低资源占用而缩放、压缩或降低剪贴板原图分辨率。
- 改写截图捕获后端或改变多显示器截图策略。
