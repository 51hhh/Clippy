# 恢复图片剪贴板入口并修复 OCR 侧栏滚动

## 背景

主窗口在 `11bacf8` 中新增了“打开图片”按钮和全局 `Ctrl/Cmd+O` 文件选择入口，破坏了剪贴板工具原有的轻量主界面。Clippy 已能通过系统剪贴板监听自动接收复制的图片，主窗口无需再要求用户手动选择文件。

图片详情预览目前同时存在两层滚动：外层 `.preview-content` 与被限制为 200px 的 `.preview-ocr-result`。大图会占据预览区的大部分高度，OCR 文字被挤入小区域，用户必须在嵌套滚动容器之间切换。

## 目标

- 恢复主窗口原有设计，仅通过剪贴板自动接收图片，不显示手动打开图片入口。
- 图片和 OCR 结果使用同一个预览滚动容器，向下滚动即可连续阅读完整 OCR 内容。
- 保持图片自动入队、图片预览、OCR、Pin 和可编辑 PNG 工程底层能力不回退。

## 需求

1. 移除主窗口“打开图片”按钮、错误提示以及相应样式和文案。
2. 移除主窗口全局 `Ctrl/Cmd+O` 图片选择行为，不再吞掉该系统/浏览器组合键。
3. 删除只为上述主界面入口服务的前端 IPC 包装；保留后端工程 PNG 读写能力。
4. 图片和 OCR 结果继续位于 `.preview-content` 内，由该容器统一纵向滚动。
5. OCR 结果不得再设置固定最大高度或独立滚动条，完整内容应参与外层文档流。
6. 图片从顶部开始展示并保持比例，不得因 flex 居中导致顶部内容不可达。
7. 补充回归测试覆盖主界面无打开按钮、Ctrl/Cmd+O 不被拦截、图片/OCR DOM 顺序与单滚动布局约束。

## 验收标准

- [x] 主界面静态输出不存在 `open-image-button`、“Open image”或 `Ctrl+O`。
- [x] `Ctrl/Cmd+O` 不触发图片选择器且不调用 `preventDefault()`。
- [x] 复制到系统剪贴板的图片仍由现有 watcher 自动写入历史并发送 `clip-added`。
- [x] 图片预览中图片节点位于 OCR 节点之前，两者共享 `.preview-content`。
- [x] `.preview-ocr-result` 无 `max-height` 和独立 `overflow`，长 OCR 文本完整进入外层滚动范围。
- [x] 图片保持宽高比、最大宽度不超过侧栏，并从统一滚动内容顶部开始布局。
- [x] 前端单测、类型检查、生产构建及相关 Rust 检查通过。
- [x] review 不发现 XSS、IPC 边界、键盘导航或性能回归。

## 非目标

- 不重写现有剪贴板图片监听或 OCR 后端。
- 不改变可编辑 PNG 的 iTXt 工程格式、Pin 编辑器保存语义或渲染器。
- 不把 OCR 与翻译区域合并为同一个滚动容器；本次只处理图片预览及其 OCR 结果。
